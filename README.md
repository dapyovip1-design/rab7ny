# ربحني | Rab7ny

نسخة منظمة من مشروع ربحني اعتمادًا على ملف HTML المرسل.

## محتويات المشروع
- `index.html`: واجهة الموقع.
- `js/app.js`: منطق تسجيل الدخول والمهام والعروض والمحفظة ولوحة الإدارة.
- `js/config.js`: إعداد Placement ID الخاص بـ ayeT-Studios.
- `database/secure_upgrade.sql`: وظائف وقواعد حماية مقترحة لـ Supabase.

## قبل النشر
1. خذ نسخة احتياطية من قاعدة Supabase.
2. راجع أسماء الجداول والأعمدة في مشروعك، وقارنها بما هو مستخدم في ملف SQL.
3. نفّذ `database/secure_upgrade.sql` من SQL Editor بعد التأكد من توافق المخطط.
4. أضف حسابك إلى جدول `user_roles` يدويًا من SQL Editor:
   ```sql
   insert into public.user_roles (user_id, role)
   values ('UUID-OF-YOUR-ADMIN-USER', 'admin')
   on conflict (user_id) do update set role = 'admin';
   ```
   استخرج UUID من Authentication > Users. لا تستخدم البريد كوسيلة تفويض داخل المتصفح.
5. ضع Placement ID الحقيقي في `js/config.js`.
6. اختبر التسجيل وتسجيل الدخول، إرسال إثبات، موافقة الأدمن، تعديل الرصيد، الحظر، وطلب السحب بحسابين منفصلين قبل النشر العام.

## النشر على GitHub Pages
ارفع محتويات المجلد إلى مستودع GitHub، ثم من Settings > Pages اختر النشر من الفرع الرئيسي `main` والمجلد `/ (root)`.

## مفاتيح Supabase
المشروع يستخدم Supabase URL وanon/publishable key داخل الواجهة. هذا المفتاح مخصص للعميل، لكن أمان البيانات يعتمد على RLS وسياسات قاعدة البيانات.
**لا تضع service_role key أو كلمات مرور أو مفاتيح سرية في GitHub أو ملفات JavaScript.**

## تنبيهات توافق مهمة
- ملف SQL يفترض وجود الأعمدة التي ظهرت في التطبيق: `profiles(id,email,balance,is_banned,ban_reason)` و`site_settings(id,points_per_dollar,min_withdraw,max_withdraw)` وحقول الجداول الأخرى المستخدمة في التطبيق.
- إذا كان مخطط قاعدة البيانات لديك مختلفًا، لا تنفذ ملف SQL قبل تعديله ليتوافق.
- سياسات RLS permissive القديمة قد تظل تسمح بالوصول؛ راجع واحذف أي سياسة قديمة واسعة مثل `USING (true)` على الجداول الحساسة. سياسات PostgreSQL permissive تتجمع بمنطق OR.
- إدارة السحب في الواجهة الحالية تعرض الطلبات وحالتها؛ لا تحتوي على زر لتعليم الطلب بأنه مدفوع.
- رابط ayeT-Studios لن يعمل حتى تضيف Placement ID الحقيقي.
- راجع إعدادات Auth > URL Configuration في Supabase وحدد Site URL وRedirect URLs الخاصة بعنوان النشر.

## ما تم تحسينه في هذه النسخة
- استبدال فحص الأدمن بالبريد بفحص دور مخزن في قاعدة البيانات.
- تحويل طلب السحب إلى RPC واحدة تخصم الرصيد وتنشئ الطلب في معاملة واحدة.
- تحويل قبول إثبات المهمة إلى RPC تمنع الموافقة المتكررة وتضيف النقاط وتحدث الحالة في معاملة واحدة.
- إضافة RPC محمية لتعديل الرصيد والحظر.
- عرض نص الإشعارات كنص عادي بدل إدخاله مباشرة كـ HTML.
- نقل Placement ID إلى ملف إعدادات منفصل.
